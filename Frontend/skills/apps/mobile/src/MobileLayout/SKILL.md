---
name: mobile-layout
description: Mobile authenticated shell and navigation.
---

MobileLayout.tsx hosts authenticated routes, the menu bar, and page action bars. The notification bell, More button, and floating Home, Album, Place, and User menu items remain mounted across authenticated routes. The `.mobile-menu-bar` uses `data-item` values to move its indicator between active items, including on browser history navigation. On secondary pages with no menu item, the indicator is hidden. The active item follows the route and uses `aria-current`.

On Home, the bordered avatar, username, and localized role come from the signed-in account and link to Profile. The Album, Place, and User menu items open `/album`, `/location`, and `/user`, with matching page titles. The Album list uses the Home tab. Navigation between the Album list and album detail skips the page overlay in both directions and preserves the Album header title. Album detail shows Back to return to the list. Android Back dismisses the Add album dialog before leaving the list. Place and User keep Back inert. More pages keep their gradient title and Back button. The title uses a blue, purple, and pink layered gradient that loops when interface motion is enabled. More's icon morphs with the dialog. Motion follows the interface setting and system reduced motion.

Bottom tabs slide below the viewport and become inert on album detail. The shell clips them below the viewport, so scrolling cannot reveal them. The gradient plus stays mounted at the same center point. On the list it enables Add album when the list is ready. On detail it expands to the menu width for eligible contributors and reveals the Add media label with Animate UI Splitting Text. The shell keeps Back mounted and inert on the list. When detail opens, the Album title shifts to make room and Back slides and fades in. The list frame fades while the album title and visibility byline move between their list and detail positions in browsers with View Transition support. The detail route preloads its metadata for this handoff. Motion respects the interface setting and reduced-motion preference. The center action and shared primary buttons loop their gradients when interface motion is enabled and the system allows motion. The expanded Add media button has no inset highlight. Header controls use 20 px icons. Bottom tabs and the center action use 24 px icons. Hovering the enabled action turns the plus icon when interface and icon motion are on. The round action is 56 px across. Tabs have at least 48 px touch targets and a 4 px icon-to-label gap.

Profile uses the same bottom-control transition. The menu slides down and becomes inert while the center button expands into text-only Save avatar. It stays visible while disabled during loading, without a draft, and during a save. Leaving Profile restores the menu.

Dragging horizontally from the current menu item moves the indicator by the pointer's horizontal displacement, clamped to the first and last tab in either writing direction. The nearest tab gets the preview styling, while `aria-current` follows the committed route. Release over another tab to settle the indicator from its current position and start loading through `useOpenMobilePage`. Release outside the tabs or cancel the pointer to restore the route highlight.

A horizontal drag from an inactive tab or the bar padding moves one tab from the current route in the drag direction. The preview stops at the adjacent tab, even on a long drag. Release commits through `useOpenMobilePage`. At the ends of the bar, a drag outward stays on the current tab. Secondary pages without a current tab still support direct taps. Taps, keyboard activation, vertical touch gestures, and pinch zoom retain their usual behavior.

The More button opens a modal bottom sheet with User profile, Upload (/upload), Settings (/setting), and Log out. The sheet slides up when opened and down when dismissed. Tapping the backdrop or pressing Escape closes it and returns focus to the More button. Selecting a destination closes the sheet before navigation. Log out closes it and calls the shared logout hook. Appearance controls live on the Settings page.

The shell and its page-loading overlay share the mobile theme background. The notification, More, and Back buttons share flat, borderless styling. In dark mode, all three use the raised fill to stand out against the header. The floating navigation, More sheet, and notification panel use the shared raised fill, which is `#303030` in dark mode. The floating navigation has 12 px corners and soft exterior shadows. It has a subtle light-mode border and keeps the same spacing with a transparent dark-mode border. Home uses Activity, Album uses Camera, Place uses Compass, and User uses User Round. Selected icons and labels are white in dark mode and charcoal in light mode. Camera, Compass, and User Round use a fill when selected. Inactive tabs keep gray outlines and labels. Activity keeps the same outline and stroke width in both states. Its stroke uses the selected color when highlighted. Hovering the Home tab briefly pulses the Activity icon when interface and icon motion are enabled and reduced motion is off. The selected User icon uses a flat lower edge. Selected tabs share the menu bar surface. Cutouts in filled icons use that surface color. Labels use weight 500 in every state. The current label is distinguished by its color. The bar overlays the scroll area, so content can pass underneath it and remain visible around it. Scroll containers add bottom clearance to bring their last items above the bar. Page action bars use that same clearance to sit above the tabs.

`layout/mobilePageNavigation.tsx` records the source entry and carries Home's history index across page links, menu items, and filter URL changes. The Home item and Back from More pages return to that Home entry or replace the current entry with Home after a direct visit. Android Back closes an open immersive album viewer first. Back on album detail otherwise returns to the previous Album entry when opened from Album. Direct entry and other origins replace album detail with `/album`. Page links from a More destination immediately above Home replace that destination's entry, so browser Back can go directly to Home.

Mobile navigation shows the progress overlay immediately inside the page body, even for cached routes. Header controls and tabs remain available. Covered route content is inert while the destination loads. The destination mounts and starts its queries at commit. The progress bar moves in one-percent steps over 500 ms. At 100%, the cover fades over 400 ms while a changed destination title slides into the header. Matching titles keep the same visible node and gradient through navigation. Overlay motion runs independently of Interface motion and respects system reduced motion.

Bottom controls hide when an editable field is focused and the viewport shrinks for the keyboard. They return when the viewport or focus returns.
