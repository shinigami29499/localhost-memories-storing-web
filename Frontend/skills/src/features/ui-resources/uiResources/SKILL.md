---
name: ui-resources
description: Cache public UI files and report component loading before page data requests.
---

`uiAssetsPlugin.ts` writes `/ui-assets.json` for the web and mobile builds. It lists public Vite assets and static dependencies for lazy route modules. `UiBootstrap.tsx` prepares the build in Cache Storage and warms registered route and dialog modules before starting the router. Development warms the modules within the current document. Capacitor uses packaged files. The first preparation screen lists package states and offers Open app when all items are ready. Opening starts the Home route for a signed-in session and delivers its welcome toast. Signed-out visitors open Sign in. The prepared initial route skips the second overlay.

Active superadmins can skip first-load preloading in ordinary browser tabs. The preference applies after reload. Standalone PWA launches and native builds ignore it. The cache accepts public build files only. API responses, hubs, protected media, and authenticated requests stay outside it.

`uiRoute.tsx` prepares route files using the React Router navigation request signal. The progress bar counts completed assets and the resolved route module. By default, the web and mobile shells show the route overlay immediately for pathname changes, including cached routes and back navigation. It remains visible for 500 ms or until the route is ready, whichever comes later. The visual progress bar fills in one-percent steps over 500 ms and caps at 99% while the route loads. Same-path filter and dialog changes do not trigger it. Switching routes aborts outstanding asset fetches and prevents the old page from mounting. An import already started by the browser can finish and be reused.

`RouteLoadingProvider` accepts a pathname pair predicate that suppresses overlay rendering during loading and commit. Mobile uses it for navigation between the Album list and album detail in both directions. The route loader still prepares the destination normally. The overlay retains its source pathname through the fade so the mobile shell can preserve a matching header title.

The destination mounts and starts its page queries as soon as the loader resolves. Once the route is ready and the fill time has elapsed, the bar reaches 100% and the route overlay fades out over 400 ms. On mobile, any destination header title slides into place during the same interval. Interface motion does not control route overlay animations. System reduced motion skips them. A new destination replaces any overlay that is fading. Startup fallbacks report combined pending work to a persistent boundary. The startup overlay yields to the first page transition. Inline data placeholders use a 200 ms delay and disappear as soon as their content is ready. Unmounting cancels pending feedback timers.
