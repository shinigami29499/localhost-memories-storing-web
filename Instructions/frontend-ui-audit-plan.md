# Frontend UI audit and improvement plan

## Scope and evidence

Audited all 16 current route states from `Frontend/src/App.tsx` on 6 November 2026. Playwright visited each at 1440×900 and 390×844 with an admin session and mocked, mostly empty API data. All 32 visits rendered without page errors or horizontal overflow. The backend was not started. Mapbox was unavailable in this pass, so the map routes show their failure states. Populated media, upload, map, and user lists still need a later data-backed visual pass. The linked articles' text was read; their example images could not be rendered in this environment.

The standard for new work is [frontend-ui-standard.md](frontend-ui-standard.md). The tables below preserve the original baseline and priorities. The execution record states what changed.

## Execution record

Implemented the shared confirmation contract across its callers: action-specific labels, neutral Cancel, dangerous styling on destructive confirmation, and Cancel focused first. Added visible phone labels for primary gallery, album, and upload actions; added next-step actions to empty Home, Favorites, Albums, and Saved places states. Added one semantic `h1` per route, restored the album detail title/caption on phones, clarified registration constraints and password mismatch near the field, removed empty Users and History pagination, and shortened map failure copy with Retry. Album delete is visually secondary, and phone upload batch controls now have a separate row.

Playwright revisited all 16 routes at 1440×900 and 390×844 in empty and representative populated states (64 visits). No page errors or horizontal overflow were observed. A focused second pass checked album detail, gallery, trash, upload, and registration after layout fixes. The frontend build, TypeScript check, and focused confirmation/Home tests passed.

Mapbox could not load in this environment, so real marker interactions remain unverified. Representative API mocks used four sample media, one album, one upload batch, and one user; they do not prove behavior with large or diverse production data. The full Vitest suite currently fails in 23 files, including stale assertions about headings, controls, and unrelated map mocks. Do not treat those failures as proof of this UI pass; update the affected tests as their respective screens are changed.

## Order of work

1. Fix the shared confirmation contract and review each destructive caller. This resolves the highest-risk inconsistency across routes.
2. Improve persistent labels for primary phone actions and empty-state next steps. Recheck gallery, albums, and uploads at both widths.
3. Resolve heading semantics and redundant zero-result pagination. Keep the top bar compact on phones.
4. Run a second visual pass with representative populated data, long localized copy, and a working map; then refine cards, controls, spacing, and states based on those captures.

For each item, inspect desktop and phone rendering, keyboard focus, loading/empty/error/success states, and the behavior after action or cancellation. Follow the frontend overview's validation policy; do not treat the mocked baseline as proof of populated flows.
